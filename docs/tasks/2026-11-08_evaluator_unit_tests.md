**素材处理规则：**
- 把 `video.mp4` 解码一次，存成 uint8 RGB 数组 `(240, 768, 768, 3)`，作为 `clean.npy`。
- 所有改动都在这个数组上做，改动后的视频一律存成 `.npy`，**不得重新编码成 mp4**，避免压缩引入的噪声。
- 音频统一为 16 kHz、16 位 PCM 的 wav。
- 每个样本都要把 `clean.npy` 跑过全部评价器，作为基线。

- 统计“窗口外”时，窗口两侧各排除 6 帧过渡带。

### 2.3 六项测试

评价器用仓库现有脚本，调用方式见 `scripts/quality/run_quality.sh`。各项要用的脚本：
- 口型：`scripts/evaluators/eval_lipsync.py`
- 身份：`scripts/evaluators/score_emotion_refs.py`（ArcFace）、`scripts/evaluators/eval_identity_dino.py`
- 姿态：`scripts/evaluators/extract_dwpose.py` → `scripts/evaluators/eval_pose.py`
- 时序：`scripts/evaluators/eval_temporal_evidence.py` → `scripts/evaluators/eval_temporal_context.py`
- 情绪：`scripts/evaluators/score_emotion_refs.py` → `scripts/evaluators/eval_emotion_explicit.py`
- 手部可见度：`scripts/evaluators/eval_hand_joint_visibility.py`

| 编号 | 维度 | 改动（只改窗口内） | 强度档 | 用到的评价器输出 |
|---|---|---|---|---|
| T1 | Lip-sync | 只把窗口内的音频平移 k 帧（24 fps 帧；样本数 = k × 16000 / 24）；窗口外音频不动；画面不动 | k ∈ {−8, −4, −2, +2, +4, +8} | 逐段带符号偏移 `seg_offsets`、逐帧置信度 `framewise_conf` |
| T2 | Identity | 把窗口内的帧换成**下一个样本**（按 2.1 表循环）同一帧号的真人帧 | 1 档 | 逐帧 ArcFace 与本人 `reference.png` 的相似度；DINO 躯干、头发相似度 |
| T3 | Pose | (a) 冻结：帧 [a, a+12) 全部等于帧 a；(b) 跳帧：从帧 a 起用 t+6 帧替换 t 帧（末尾不够的用最后一帧补）；(c) 突跳：只把帧 a 换成帧 a+30 | 3 种 | `eval_pose` 逐帧各类异常标记（尤其 frozen、motion_jump） |
| T4 | Temporal | (a) 闪烁：窗口内偶数帧亮度 × 2^(+e/2)、奇数帧 × 2^(−e/2)（线性 RGB 上做，再转回 uint8，截断到 [0, 255]）；(b) 硬切：从帧 a 起整段换成同一视频 a+48 帧之后的内容（不够的用最后一帧补） | e ∈ {0.05, 0.1, 0.2} EV；硬切 1 档 | `flicker_score`、`flicker_flag`、`boundary_flag`、`flicker_level`（默认自然视频参照 `temporal_reference_v1.json`） |
| T5 | Emotion | 画面不改，只改**目标情绪**：正确目标 = 数据集自带逐帧 `movement:emotion_scores`（8 类，30 fps）对齐到本片段时间轴（用 `start_seconds`，30→24 fps 线性插值），按 0.5 s 段取 argmax；错误目标 = 同一段换成 2.1 表中下一个样本对应段的目标；若两者恰好相同，改取再下一个样本 | 正确 / 错误 | `eval_emotion_explicit` 的逐段一致性 |
| T6 | Hand 可见度 | 用 `clean.npy` 的 DWPose 手部关键点（置信度 ≥ 0.3）取**右手**外接框，四周各扩 20%，窗口内每帧用灰色 (128, 128, 128) 实心矩形盖住；该帧右手无有效关键点则不盖，并记录 | 1 档 | `visible_joint_fraction`、`mean_joint_visibility`；若脚本内部已有分手结果，可新增分手输出（不得改变原有输出的数值） |

说明：
- T5 的数据集情绪标签是 Meta 模型自动标注的，**不是人工真值**，报告里必须这样写明。若仓库里已有 RAVDESS 显式目标情绪验证的脚本和数据（见 `docs/status/evaluator_research_20261002.md` 及 `ravdess_*` 相关文件），原样复跑一次并报告 AUC，与之前的 0.9253 对比；找不到就写明“未复跑”，不要另造。
- T1 的符号约定以 `src/quality_state.py` 中 `LIP_OFFSET_NOTE` 为准：音频推后 d 个 25 fps 帧，读数为 −d。24 fps 的 k 帧约等于 25 fps 的 k × 25 / 24 帧。

### 2.4 预先登记的通过标准（不得事后修改阈值或标准）

每项测试按“人”判定：8 人中**至少 7 人**在 W1、W2 两个窗口**都满足**，该项才算通过。

| 测试 | 单人通过条件 |
|---|---|
| T1 | 对 \|k\| ∈ {4, 8}：窗口内各段带符号偏移的中位数等于期望值 ±1（25 fps 帧）；窗口外 ≥ 90% 的段 \|偏移\| ≤ 1；窗口内平均置信度低于 clean 同段。k = ±2 只报告、不判定（低于 SyncNet 分辨率） |
| T2 | 窗口内 ArcFace 平均相似度比 clean 同段下降 ≥ 0.30；窗口外平均变化 ≤ 0.02 |
| T3 | (a) frozen 标记覆盖冻结帧的 ≥ 80%，且 [a−3, a+15) 之外不新增 frozen 标记；(b)(c) 在 a ± 2 帧内出现 motion_jump 标记；三种改动在其他位置新增的标记总数 ≤ clean 的标记数 + 1 |
| T4 | (a) 窗口内平均 flicker_score 随 e 严格单调上升；e = 0.1 时窗口内 flicker_flag 比例 ≥ 50%；窗口外 flag 比例 ≤ clean + 2 个百分点。(b) boundary_flag 出现在 a ± 1 帧 |
| T5 | 正确目标的平均一致性 > 错误目标；另报 8 人合并的段级 AUC（正确 vs 错误） |
| T6 | 窗口内被遮挡帧的 visible_joint_fraction 比 clean 同帧平均下降 ≥ 0.30（若有分手输出，用右手）；窗口外平均变化 ≤ 0.05 |

**跨维度副作用（只报告，不判定）：** 每个改动都要跑全部六个评价器，报告非目标维度在窗口内外相对 clean 的变化，标出变化最大的前 5 项。

### 2.5 不通过时怎么办

- 不得调阈值、不得改参照文件、不得换样本或换窗口来让测试通过。
- 对每个未通过的人：保存相关帧截图（窗口前后各 3 帧）和评价器原始输出，写出你判断的原因，归为三类之一：A. 评价器本身的问题；B. 测试改动没有真正生效（例如改动后画面实际没变）；C. 无法判断。
- 某个评价器的环境跑不起来：记录完整报错，跳过它，继续其余测试，不要重装或升级环境。

### 2.6 实现自检（防止代码实现错误，必须先过再跑评价器）

本任务的结论完全依赖“改动确实按规定生效”和“读数确实按约定解读”。旧项目曾因关键点编号用错（读到眼睛附近的点）、只查绝对值不查方向等实现错误得出错误结论，所以下面每一条都要写成自动检查，在报告里列出结果；任何一条不过，先修实现，不得跳过。

**A. 改动校验（每个改动产物都要做，结果写进 `edit_meta.json`）**
- 画面类改动（T2、T3、T4、T6）：逐帧与 `clean.npy` 比较，**实际被改的帧集合必须与预定集合完全相等**（半开区间、从 0 开始计数），其余帧必须逐字节相同。
- T1：窗口内用互相关验证音频平移量等于 k × 16000 / 24 个采样点（误差 ±1 个采样点），方向与 k 的符号一致；窗口外音频逐采样相同。
- T2：确认替换进来的帧来自 2.1 表中不同人物，且帧号与原帧号相同。
- T3：冻结段每一帧都与帧 a 逐字节相同；跳帧的“新帧号 → 原帧号”映射逐帧核对；突跳只改了帧 a。
- T4：在未截断的像素上，线性 RGB 下偶数帧与奇数帧的平均亮度比 = 2^e（误差 ±5%）；报告被截断到 0 或 255 的像素比例。
- T5：时间对齐用合成数据单测：给定 `start_seconds` 和 30 fps 序列，第 t 帧（24 fps）取到的数据集下标应为 (start_seconds + t / 24) × 30；报告每个样本有效情绪标签的段数比例。
- T6：遮挡框必须包住该帧右手全部有效关键点（覆盖率 100%）；报告每个样本被跳过的帧数。

**B. 读数约定核对（在报告里逐条写出你确认后的约定和依据代码行）**
- 帧号从 0 开始、区间半开；段 = 12 帧（0.5 s）。
- Lip-sync 内部转为 25 fps，段读数如何映射回 24 fps 的段；偏移符号约定以 `src/quality_state.py` 的 `LIP_OFFSET_NOTE` 为准，并用整段平移（`--audio_shift_frames`）实测一次确认。
- Temporal：帧对 (t−1, t) 的边界读数记在帧 t（见 `eval_temporal_context.py` 说明）；据此计算 T4(b) 的期望帧。
- 各评价器“测不到”时输出 NaN 的位置，统计时一律排除，不当作 0 或“正常”。
- 手部关键点的左右手顺序和编号，用 DWPose 输出在 1 帧上画图核对，确认“右手”取对了。

**C. 单元测试与确定性**
- 为 `make_edits.py` 的每个改动函数写 pytest 单测（用小的合成数组），放在 `tests/test_evaluator_unit_edits.py`，全部通过。
- 在 CRB100_001 的 clean 上把每个评价器连跑两次：结果应逐元素相同；若不同，报告差异幅度。这个幅度就是判断“变化是否显著”的噪声底线。

**D. 先试点再全量**
- 先只跑 CRB100_001 × W1 × 全部测试，生成读数曲线和预览视频，确认 A–C 全部通过、预览里能看到预期的改动，再跑其余 7 个样本和 W2。试点结果单独提交并推送一次。

### 2.7 关键规定的原因（帮助你理解，避免“看起来合理”的改写）

| 规定 | 原因 |
|---|---|
| 改动视频存 npy，不重新编码 mp4 | 有损压缩会改动窗口外的像素，并在时序评价器上制造假闪烁 |
| 窗口、强度、样本预先写死 | 防止看到结果后挑对自己有利的设置，结论才可信 |
| 不许调阈值、改参照文件 | 本任务检验的是现有评价器；改了就不再是在测它 |
| 8 人至少 7 人通过 | 只在一两个人身上成立的结果，换人就可能失效（旧项目和本项目早期都只测过 1 人） |
| 测不到记 NaN | 填 0 会被误读为“测过了，结果很差”或“正常” |
| 每个改动都跑全部六个评价器 | 要看副作用：例如旧项目的换脸同时改变了口型分 |
| 预览视频必须并排、带标注 | 负责人要用眼睛确认改动真实发生、程度合理，数字和画面要能对上 |

## 3. GPU 规则（用户 2026-11-08 明确要求）

- **GPU 3 永远不得使用**；`CUDA_VISIBLE_DEVICES` 不得包含 3。
- 需要 GPU 的步骤（光流、DINO、手部可见度等），可以使用**空闲显存足够**的卡，即使卡上有其他用户的进程。条件：该卡空闲显存 ≥ 本步骤预计峰值 + 4 GB 余量。每次启动前用 `nvidia-smi` 确认。
- 优先选完全空闲的卡；都不空闲时，选空闲显存最多、利用率最低的那张。
- 绝不终止、暂停或影响其他用户的进程；任务结束（包括失败）后释放所用的卡。
- 能用 CPU 跑的（DWPose、SyncNet、ArcFace、情绪）一律用 CPU，并用 `taskset` 或线程上限控制，不超过 32 个核。
- `scripts/evaluators/eval_hand_joint_visibility.py` 里硬编码了“只允许 GPU0 或 GPU1”的检查，这是 2026-10-14 之前的旧规则。允许把它改成“不允许 GPU3、其余可用”，只改这一处判断，并在报告里写明改动。
