## 0. 为什么有第二版

第一版试点（CRB100_001 × W1）结束后，负责人和 Claude 逐项核对了原始读数，结论是：

| 测试 | 试点表现 | 判断 |
|---|---|---|
| T1 口型 | 窗口内偏移方向、大小全部正确；窗口外读数与 clean **完全相同** | 第一版用“窗口外绝对偏移 ≤ 1”判定，而 clean 自己在第 1、5 段就有 −6、−9 的读数（停顿处 SyncNet 本身不准）。**标准写错了**，评价器没问题 |
| T3 突跳 | 在第 94–98 帧出现 motion_jump / jerk 标记 | 单帧突跳会在进、出两侧留下标记，属于**同一个事件**；第一版把它们算成“多余标记”，**计数规则写错了** |
| T3 跳帧 | 第 96 帧附近无标记；clean 在第 122 帧的标记移到了第 116 帧（正好提前 6 帧） | 评价器看得见时间位移，但该时刻手速慢，少掉 0.25 秒动作本就不可见。**真实局限**，不宜作为单一通过条件 |
| T4 持续闪烁 | `flicker_level` 窗口均值 0.032 / 0.047 / 0.100 EV（clean 为 0），随强度单调；`flicker_flag` 全为 0 | `flicker_flag` 是为**瞬时异常**设计的，48 帧持续闪烁会被当成“片内常态”。第一版**选错了输出**；持续闪烁应看 `flicker_level` |
| T6 手部可见度 | 遮挡后窗口内平均检出手数从 2.1 降到 0.3，`visible_joint_fraction` 却从 0.805 升到 0.888 | **评价器定义缺陷**：只在“检测到的手”里统计，没检测到的手不计入，于是越挡越“可见”。另外第一版取的“右手”编号（hands 下标 0）需要核实 |
| — | 试点没有生成预览视频；报告缺少自检 A、B 的逐条结果 | 未按第一版 2.6-D 执行，本版补做 |

**诚实要求：** 第二版的通过标准是在看过试点结果之后修订的。报告中必须：
- 原样保留第一版标准下的试点结果，不删除、不改写；
- 写明每条标准为什么修订（引用上表）；
- 单独列出“CRB100_001（试点，标准修订时已看过其结果）”和“其余 7 人（标准修订后首次运行）”两组结果。**最终是否通过，以其余 7 人为主要依据**：7 人中至少 6 人满足，才算该项通过。

## 0.5 代码审查发现（必须在重跑前改掉）

Claude 逐行审查了第一版的 `make_edits.py`、`run_tests.py`、`analyze.py`，发现以下实现问题。逐条修改，每条在报告中写明改了哪几行、怎么验证的。

| 编号 | 位置 | 问题 | 要求 |
|---|---|---|---|
| C1 | `config.json` 的 `right_hand_index: 0`；`analyze.py` 的 `right_hand_visibility()` | **左右手口径不一致**：遮挡按 DWPose `hands[0]` 画框，判定却读 WiLoR 的 `region_is_right`。若 `hands[0]` 是人物的左手，那么第一版挡的是左手、测的是右手，“遮挡后右手可见度反而上升”可能就是这个原因 | 先完成第二部分第 1 条的编号核实，再让遮挡和判定都用**同一只手**（人物自己的右手）；在报告里给出第一版到底挡了哪只手的结论 |
| C2 | `make_edits.py` 的 `shift_audio_window()` | 平移后空出的部分**填了静音**：推后 8 帧时，窗口开头有约 0.33 秒的静音。这会让口型评价器同时受到“错位”和“突然静音”两种影响，混淆了测试 | 改成**用窗口外相邻的真实音频补齐**：推后 n 个采样点时，`out[start:end] = audio[start-n:end-n]`；提前时，`out[start:end] = audio[start+n:end+n]`。窗口外音频仍逐采样不变；互相关校验照旧，并更新单测 |
| C3 | `make_edits.py` 的 `skip_forward_window()` | 跳帧只作用于窗口内 [a, b)，所以在 a 处向前跳、在 b 处又**向后跳回**，产生两个事件。第一版任务书写的是“从帧 a 起”，两者不一致，是任务书的歧义 | **保持只作用于窗口内**（与其他改动一致），任务书以此为准；报告时分别给出 a ± 2 和 b ± 2 附近的标记情况（第二版中跳帧只报告、不判定） |
| C4 | `analyze.py` 的 `t3()` | 突跳“新增标记”统计的是**全片所有类型标记的总数差**，事件本身在 a 前后产生的标记也被算成“多余”；检出条件只认 motion_jump、不认 jerk | 按第二版第 4 节重写：[a−2, a+2] 内 motion_jump 或 jerk 算检出；只统计该区间之外、且不在 clean 已有标记帧上的新增标记 |
| C5 | `analyze.py` 的 `by_person_both_windows()` | T3 把冻结、跳帧、突跳三者“全部通过”才算通过，T4 把持续闪烁和硬切捆在一起 | 按第二版第 4 节，T3 冻结、T3 突跳、T4a、T4b、T4c 各自单独判定；T3 跳帧不参与判定；“通过”的人数门槛改为“其余 7 人中至少 6 人”，试点样本单列 |
| C6 | `analyze.py` 的 `t1()` | 窗口外判据用的是绝对偏移 ≤ 1 | 改为“与 clean 同段相差 ≤ 1”。期望值沿用代码里的 −k × 25 / 24（**不取整**），容差 ±1 |
| C7 | `analyze.py` 的 `t4()` | 硬切的帧号用 `np.flatnonzero(boundary_flag) + 1` 换算，这依赖 `boundary_flag` 长度为 239、第 j 个元素对应帧对 (j, j+1) | 加断言检查长度确为 239，并在报告中引用 `eval_temporal_context.py` 或 `src/quality_state.py` 中证明该约定的代码行；T4a 改用 `flicker_level` 判定 |

另外：第一版没有改动 `eval_hand_joint_visibility.py` 的 GPU 检查（只允许 GPU0、GPU1），说明手部测试是在这两张卡之一上跑的。第二版允许按第一版第 3 节放宽这一检查。

## 3. 第三部分：修复手部可见度评价器（负责人已批准修改评价器逻辑）

对 `scripts/evaluators/eval_hand_joint_visibility.py` 做**只增不改**的修改：原有输出字段的数值必须与修改前逐元素一致（修改后在 clean 上回归验证，结果写入报告）。

新增可选参数 `--expected <npz>`，提供每帧“应当出现的手”：

- 字段 `left_box`、`right_box`：形状 `(T, 4)`，像素坐标 xyxy；该帧不应出现这只手时为 NaN；
- 单元测试中由 clean 视频的 DWPose 手部关键点（置信度 ≥ 0.3，至少 5 个点）生成；以后用于生成视频时由手部姿态计划生成（本任务不涉及）。

新增输出（逐帧，形状 `(T,)`）：

| 字段 | 含义 |
|---|---|
| `vis_left`、`vis_right` | 该手的关节可见度：应出现且检测到 → WiLoR 的可见度；**应出现但没检测到 → 0**；不应出现或该帧未采样 → NaN |
| `missing_left`、`missing_right` | 应出现但没检测到 → 1；检测到 → 0；不应出现或未采样 → NaN |

**匹配规则：** 检测到的手区域与期望框的 IoU ≥ 0.3，且 `region_is_right` 与期望的左右一致，才算“检测到这只手”；一只期望手只能匹配一个区域，多个候选时取 IoU 最大的。

为匹配规则和“应出现但没检测到 → 0”写 pytest 单测，放进 `tests/test_hand_visibility_expected.py`，全部通过。
