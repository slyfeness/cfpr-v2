## 0. 背景与性质

**第 3 步的结论：** 在脸部 token 上做线性混合（新 = (1−α)·本人 + α·供体），到 α = 0.4 时，和本人的 ArcFace 相似度下降 0.2–0.6，但和供体的相似度基本不变。负责人看过截图：脸被**抹平**了（五官、眼镜逐渐消失），并没有变成供体。原因很可能是：两张脸特征的平均值不对应任何一张真实的脸。

**本任务是探索性试点：** 换几种注入方式，找一种能让窗口内的脸**真正变成供体、且不糊**的方法。本任务**不登记验收门槛**，但第 4 节的“候选标准”必须在看结果之前就按原样执行，不许挑着报。找到候选方法后，负责人会另写正式任务书，登记剂量矩阵。

**附带：** 把第 3 步的 16 条预览补发到 PR #3（见第 6 节）。负责人已同意公开 Seamless 数据集人物的预览视频。

## 1. 固定设置

- 样本：CRB100_001（供体 CRB100_002）、CRB100_025（供体 CRB100_050）。两组都是外貌差异很大的组合（性别、发型、胡子、眼镜），肉眼好判断。
- 240 帧，种子 3407，只用窗口 W1 = [96, 144)。
- 脸框、供体对齐图、读取端层的排序，全部沿用第 3 步的 `alignment/` 产物和 `identity_edit.py`，不重新计算。
- 上下文权重 w 的规则与第 3 步相同：只有和窗口重叠的上下文才改，w 等于重叠比例；不重叠的上下文放回原对象。除第 2 节明确写明的例外，所有变体在 w < 1 的过渡上下文里按 w 缩放：替换类变体，用 w 作为“替换概率 / 混合强度”；拼接类变体，只在 w ≥ 0.5 的上下文里拼接。实现时记录每个上下文实际做了什么。
- clean 版本直接复用第 3 步的 `clean_a`，不重新生成；复用前核对 `raw_output_sha256` 和第 3 步记录的一致。

## 2. 变体（每人各生成 1 条，共 2 × 8 = 16 条）

| 编号 | 名称 | 做法 | 想回答的问题 |
|---|---|---|---|
| P0 | 整图替换（阳性对照） | 窗口内把读取端**所有层、所有 token** 换成**供体原始参考图**（不对齐）的库 | 生成器在本人的姿态下，能不能画出供体？ArcFace 能不能读出“像供体”？这是上限 |
| P1 | 脸部 token 整块替换 | 脸框内的 token 直接换成对齐供体的 token（强度 1，不做平均），所有层 | 不做平均还会糊吗？ |
| P2 | 只换高分辨率层 | 同 P1，但只换 token 数最多的那一组层（按 token 数分组，取最大的一组） | 身份主要由哪一级特征决定？ |
| P3 | 只换低分辨率层 | 同 P1，但只换 token 数最少的一组 | 同上 |
| P4 | 按比例随机替换 50% | 脸框内随机选 50% 的 token（固定随机种子 0，每层独立抽，整个窗口固定不变），整块换成供体的；其余保持本人 | “按比例换”能不能当剂量用，而且不糊？ |
| P5 | 拼接供体脸部 token | 本人的库不动，在 `bank` 列表里**追加**一项：对齐供体脸框内的 token。注意力会同时看到两份 | 让注意力自己选，而不是在特征上取平均 |
| P6 | 拼接 + 移除本人脸部 | 本人的库去掉脸框内的 token，再追加供体脸框内的 token | 和 P1 的 token 集合相同，但放在不同位置，用来核对 P1 的实现。理论上 P6 应与 P1 的结果非常接近 |
| P7 | 像素级换脸参考图 | 用对齐供体图的脸框区域，在**本人参考图**上做 `cv2.seamlessClone`（掩膜取脸框内接椭圆，NORMAL_CLONE），得到“本人身体 + 供体脸”的新参考图；用它跑 reference UNet 得到新的库，在窗口内整库替换 | 在“身份原型”层面换脸，是否最自然？ |

补充说明：

- P5、P6 改变了 `bank` 的 token 数。这是官方注意力代码本来就支持的（`bank` 列表里的各项会沿 token 维度拼接），**不改官方代码**。
- P7 要保存那张新参考图，供人工核对。
- 所有变体都只能通过 `ctx_edit` 实现，**不改 `src/acc_core.py`**。

## 3. 测量

每条视频（包括复用的两条 clean_a）都要测：

1. 窗口内逐帧 ArcFace：分别对**本人**原参考图、**供体**原参考图（沿用第 3 步验证过的封装）；
2. **脸部清晰度**：在逐帧人脸检测框内计算灰度图拉普拉斯方差，报告窗口内均值，并除以 clean 同帧均值，得到“清晰度比”；
3. 窗口外（离窗口 24 帧以上）对本人的 ArcFace 变化，用来确认没有外溢；
4. 有效人脸帧数。

**另外：** 每人一张截图拼图，取第 108、120、132 帧的脸部区域（用逐帧检测框，不要用参考图脸框）。每行一个变体，最左边是 clean，最右边是供体参考图的脸。

## 4. 候选标准（事先写定，看结果前就生效）

一个变体要算“候选”，**两个人都**要满足：

- 窗口内对**供体**的 ArcFace 上升 ≥ 0.15；
- 窗口内对**本人**的 ArcFace 下降 ≥ 0.30；
- 清晰度比 ≥ 0.8；
- 窗口外对本人的 ArcFace 变化绝对值 ≤ 0.02。

报告里要列出全部 8 个变体的这四个数，标明哪些满足、哪些不满足。不得因为结果不好看就删掉变体，也不得新增本节没写的变体。

P0 是阳性对照，不参与候选。如果 P0 本身都达不到“供体上升 ≥ 0.15”，就说明在这个生成器加这个评价器的组合下，“换成指定的人”可能根本测不出来。这时在报告首段写明这一点，其余结论都要以此为前提来读。
