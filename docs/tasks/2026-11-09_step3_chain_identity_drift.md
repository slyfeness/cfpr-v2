## 1. 这一步要回答什么

和第 2 步一样，走通“注入 → 记录 → 测量 → 修复”闭环，这次的故障是**身份漂移**：在**生成过程中**，只在指定窗口内，把参考特征里“脸”的部分按比例 α 混入另一个人（供体）的特征。要验证四件事：

1. **注入生效：** 窗口内的脸变得不像本人、更像供体；
2. **只在窗口内：** 窗口外基本不受影响；
3. **剂量单调：** α 越大，漂移越强；
4. **修复：** 去掉改动重新生成，结果与干净版本逐字节相同。

## 2. 背景：ACC 的参考特征和已有钩子

- ACC 先用 reference UNet 处理参考图，把每个 transformer 块的特征存进“参考特征库”（`bank`）。去噪时，每一帧都通过注意力去读这个库，靠它记住“这个人长什么样”。
- 读取端的库在一个 12 帧的上下文窗口内**对所有帧相同**，所以无法逐帧修改，只能**按上下文窗口**修改。
- `src/acc_core.py` 的 `ctx_edit(t_i, frames, reader)` 钩子，会在每个 12 帧上下文去噪之前被调用，可以在这里替换读取端的库。**本任务不改 `acc_core.py`，只用这个已有钩子。**
- 已有两个脚本可以参考：
  - `scripts/evaluators/gen_emotion_switch.py`：按上下文窗口软混合读取端的库，权重 w = 本上下文中落在区间内的帧所占的比例；
  - `scripts/evaluators/gen_identity_dose.py`：只混合脸框区域的特征。
- **注意：** `gen_identity_dose.py` 有一个缺陷。它直接取供体特征图上“和本人脸框同一位置”的特征，但供体的脸不一定在那个位置，混进来的可能是供体的背景。本任务必须先对齐供体，见 3.2。
- 先前的单人实验（CRB100_001，供体 CRB100_002，全片混合，供体未对齐）显示：ArcFace 相似度在 α = 0 时为 0.80，α = 0.25 时已降到 0.20，α = 0.5 时为 0.09。所以本任务采用更小的剂量，见第 4 节。

## 3. 注入实现

### 3.1 供体分配（预先登记）

按样本列表循环取下一个人，与单元测试 T2 相同：
001 ← 002，002 ← 025，025 ← 050，050 ← 056，056 ← 075，075 ← 087，087 ← 090，090 ← 001。
（箭头左边是本人，右边是供体。）

### 3.2 脸框与供体对齐

1. 用项目里已有的 DWPose 分别处理本人和供体的 `reference.png`，取 68 个脸部关键点（置信度 ≥ 0.3 的点）的外接框，四边各外扩框宽或框高的 25%，得到**脸框**（归一化坐标）。任一张图检测不到脸，就停止并报告。
2. **对齐供体：** 对供体参考图做“缩放 + 平移”（不旋转），让供体脸框的中心和高度对上本人脸框的中心和高度；超出画面的部分用边缘像素填充。用对齐后的供体图跑一次 reference UNet，得到供体的特征库。
3. 每人保存一张核对图：本人参考图 + 脸框、对齐后的供体图 + 同一个框，并排放置。放进报告的 media 目录。

### 3.3 混合规则

- 对读取端每一层的库，计算该层每个空间 token 的中心坐标（与 `gen_identity_dose.py` 相同）。只有中心落在本人脸框内的 token 参与混合，其余 token 保持原值。
- 每个上下文窗口的有效强度 = α × w，其中 w = 本上下文的 12 帧里落在窗口 [a, b) 内的比例。
- 混合公式：新特征 = (1 − α·w) × 本人特征 + α·w × 对齐后供体特征，用 float32 计算后转回原精度。
- w = 0 的上下文直接放回本人原始的库对象，不做任何计算。
- α = 0 的任务：钩子照常安装，但每个上下文都直接放回原始库。

### 3.4 记录与自检

每条改动视频写 `edit_meta.json`，内容包括：

- 供体、两个脸框、每层参与混合的 token 数；
- 第 0 步每个上下文的起始帧号和 w。

自检（结果写进 `edit_meta.json`）：

- w = 0 的上下文，库与原始库逐元素相同；
- 脸框外的 token 与原始逐元素相同；
- 脸框内的 token 等于按公式算出的值，误差 ≤ fp16 舍入。

另外加 pytest 单测，覆盖：脸框 token 选择、α = 0 不改动、w 的计算、混合公式。

## 4. 生成矩阵（预先登记，不得更改）

- 样本：与前两步相同的 8 人，输入为 `prepared_inputs_aligned_v1/<样本>/`。
- 每条 240 帧，种子 3407；窗口 W1 = [96, 144)、W2 = [168, 216)。
- 每人生成：
  - 干净版本 × 2，第二次用于确定性检查；
  - α ∈ {0.05, 0.10, 0.20, 0.40} × 两个窗口，共 8 条；
  - 空动作 1 条：α = 0，窗口 W1。
- 共 8 × 11 = 88 条。
- 每条保存：逐帧 PNG、`frames_uint8.npy`、`summary.json`（含 `raw_output_sha256`）、`edit_meta.json`、最终 latent、`preview.mp4`。
- 批量生成脚本 `scripts/chain_tests/generate_identity_drift.py`：加载一次模型，按任务列表依次处理。任务的 JSON 格式沿用第 2 步，`actions` 改为 `{"type": "face_bank_mix", "window": [a, b], "alpha": α, "donor": "CRB100_xxx"}`。

## 5. 测量

1. **身份评价器（主测量）：** 跑项目的人脸评价器，得到逐帧 ArcFace 与**本人** `reference.png` 的相似度（与单元测试 T2 读取的 `face_gen.npz` 口径相同）。
2. **与供体的相似度：** 再算逐帧 ArcFace 与**供体** `reference.png`（原图，不是对齐后的图）的相似度。
   - 评价器如果支持指定参考图，就用它；
   - 如果不支持，写一个薄封装，调用同一个模型、同样的预处理来计算。封装必须先复现本人参考图的已有读数（逐帧差 ≤ 1e-4），复现不了就停止并报告。
   - **不得修改评价器。**
3. **只报告的指标：** DINO 躯干和头发相似度、口型（SyncNet）、姿态、情绪，用来看副作用。调用方式与第 2 步的 `evaluate_lip_offset.py` 相同，可以复用。

## 6. 预先登记的验收标准

一律相对**干净生成版**（clean_a）的同帧读数计算：

- **窗口内变化：** 窗口 [a, b) 内各帧 ArcFace（对本人）的平均值，减去 clean_a 同帧的平均值；
- **窗口外变化：** 只取离窗口 24 帧以上的帧，即 t < a − 24 或 t ≥ b + 24，计算与 clean_a 同帧之差的平均值。为什么留 24 帧：一个上下文 12 帧，窗口两侧的上下文本身就会被部分混合，再留 12 帧给运动模块扩散的余量。

[a − 24, a) 和 [b, b + 24) 这两段过渡带只报告，不判定。

| 编号 | 检查 | 单人通过条件 |
|---|---|---|
| G1 确定性 | 干净版本两次生成 | `raw_output_sha256` 相同 |
| G2 空动作 | α = 0 vs 干净版本 | `raw_output_sha256` 相同 |
| G3 精确修复 | 去掉改动 = 干净版本 | 与 G2 等价，报告时单列说明 |
| G4 注入生效 | α ∈ {0.20, 0.40}，两个窗口 | 窗口内对本人的 ArcFace 平均下降 ≥ 0.10；并且 α = 0.40 时，窗口内对供体的 ArcFace 平均**上升**（> 0） |
| G5 窗口外不变 | 全部 α，两个窗口 | 窗口外对本人的 ArcFace 平均变化的绝对值 ≤ 0.02 |
| G6 剂量单调 | 每个窗口 | 窗口内对本人的下降量：α = 0.05 ≤ 0.10 ≤ 0.20 ≤ 0.40，允许相邻两档倒挂 ≤ 0.02（接近下限时会饱和） |

- 窗口内 ArcFace 有效帧（检测到人脸）少于窗口帧数的一半，该窗口记“无法判定”。处理规则同第 2 步：有一个窗口无法判定，此人就不计入该项分母；每项可判定的人数不得少于 5，否则记“证据不足”。
- **整体判定：** G1、G2 必须 8 人全部满足；G4–G6 在其余 7 人中至少 6 人满足（CRB100_001 单列）。
- G4 的阈值 0.10 依据第 2 节的先前单人实验设定（α = 0.25 时下降约 0.6），留了很大余量。这是**事先**设定的，不得事后修改。

### 只报告、不判定

- **剂量曲线：** 每人每窗口的“α → 窗口内对本人 / 对供体的 ArcFace 均值”曲线，8 人画在一张图上。
- **逐帧曲线：** 每条改动视频对本人的 ArcFace 随帧号变化的曲线，标出窗口和过渡带；同时画逐帧像素平均差曲线，报告影响往前、往后各扩散多少帧。
- **副作用：** DINO 躯干和头发、口型、姿态、情绪，窗口内外相对 clean_a 的变化。脸框外扩了 25%，头发区域可能被一起混合，DINO 头发下降属于预期，要在报告中说明。
- **视觉核对：** 第 3.2 节的对齐核对图。

## 7. 状态记录

每条视频写一份 `state_record.json`，按 0.5 秒段（12 帧）列出：

- **计划：** 该段的身份混合强度。用该段各帧所属上下文的 α·w 的平均值；第 0 步的上下文划分已经记在 `edit_meta.json` 里。
- **实测：** 该段对本人、对供体的 ArcFace 均值，以及有效帧数。
- **渲染信息：** 种子、窗口标记、供体。

格式与第 2 步的 `state_record.json` 保持一致，以便以后合并成统一的状态表。
