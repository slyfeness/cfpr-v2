## 2. 事后诊断

### D1 口型：改用“相对 clean 的变化量”，加置信度门槛

背景：clean 真人视频本身在多数人身上就有 −2 到 −4 帧的逐段偏移读数，登记判据却假定 clean 偏移为 0。

- 对每个改动条件、每个 0.5 秒段：变化量 = 改动后的带符号偏移 − clean 同段偏移；
- **置信度门槛：** clean 同段置信度 < 3 的段，记为“测不准”（NaN），不参与统计；另外报告门槛取 2 和 4 时的结果，看结论是否稳定；
- 对 \|k\| ∈ {4, 8}：窗口内有效段的变化量中位数，与期望值 −k × 25 / 24 的差；差 ≤ 1 记“相对准确”；窗口内有效段少于 2 个记“无法判定”；
- 逐人逐窗口列表，并统计其余 7 人中“两个窗口都相对准确”的人数（无法判定的单列）；
- 置信度一项删除：SyncNet 会在 ±15 帧内重新寻找最佳偏移，音频平移后置信度不一定下降，原判据中“置信度降低”这一条在概念上不成立，报告中说明。

### D2 口型基线偏移从哪来

clean 真人视频的 −2 到 −4 帧偏移，可能是数据集本身音画不同步，也可能是 SyncNet 的固有偏差。用一个**不依赖 SyncNet** 的方法交叉核对：

- 用 clean 的 DWPose 脸部关键点算逐帧张嘴幅度（上下唇中点距离 ÷ 两眼距离）；
- 用 `audio.wav` 算 24 fps 对齐的音量包络；
- 在 ±10 帧范围内做互相关，取相关最大的滞后；
- 8 人逐一报告：这个滞后，与 SyncNet clean 读数的整段中位数，是否一致。

结论分三种写：“两者一致 → 更可能是数据本身不同步”；“不一致 → 更可能是 SyncNet 偏差”；“无法判断”。

### D3 姿态突跳：放宽事件范围

- 把突跳的事件范围从 [a−2, a+2] 放宽到 [a−5, a+5]，重新统计“事件范围外的新增标记”；
- 对两个完全没检出的窗口（CRB100_001/W2、CRB100_075/W1），报告 clean 在帧 a 和 a+30 的双手关键点有效点数、两帧间双手质心的位移（肩宽单位），说明没检出是否因为手不可见或两帧姿态本来就接近。

### D4 时序硬切：量化切点的画面差

对每个硬切条件，计算切点 a、b 处相邻两帧的平均像素差（0–255），与 clean 同位置的相邻帧差、以及 clean 全片相邻帧差的 99 分位对比。说明未检出的切点是否是“切过去前后画面本来就很像”。

### D5 情绪：区分“标签缺失”和“判错”

- 逐人逐窗口报告数据集情绪标签的有效段数；
- 把“标签缺失导致无法测”与“测了但正确目标不高于错误目标”分开统计；
- 只用有效段，重算合并 AUC。
